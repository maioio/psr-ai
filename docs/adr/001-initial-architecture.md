# ADR-001: Initial Architecture

**Status:** Accepted
**Date:** 2026-05-16

---

## Context

PSR.ai wraps `psr.exe` - a Windows-native utility - to produce structured,
AI-readable documentation from screen recordings. The tool must work with
zero mandatory cloud dependencies, stay installable via a single `pip install`,
and run entirely on Windows without Docker or heavy runtimes.

Two structural approaches were evaluated:

- **Minimalist (A):** flat `src/psr_ai/` with all logic in top-level modules.
- **Scalable (B):** `src/psr_ai/core/` + `utils/` with a `models/` layer.

**Decision:** Hybrid D - `src/` layout with a flat `core/` and no `models/` layer.

---

## Decision

Use the `src/` layout (PEP 517 / setuptools) with modules grouped into:

| Path | Role |
|---|---|
| `src/psr_ai/cli.py` | Click command group: `sa start`, `sa stop`, `sa pub` |
| `src/psr_ai/core/` | Domain logic: recording, parsing, generating, publishing |
| `src/psr_ai/utils/` | Cross-cutting helpers: charset detection, path safety |
| `assets/psr_fallback/` | Bundled Windows shortcut for 4-tier PSR.exe resolution |

`RecordingSession` and `Step` dataclasses live in `core/parser.py` rather than a
separate `models/` directory. They are not shared across enough modules to justify
a dedicated layer at this scale.

---

## Rationale

- `src/` layout prevents accidental imports of the local package during testing
  and is the current Python packaging standard.
- Separating `utils/encoding.py` isolates the most fragile concern (MHT charset
  detection) from the parsing pipeline, making it independently testable.
- `assets/psr_fallback/` ships a `.lnk` shortcut so the 4-tier resolver can
  launch `psr.exe` even on machines where it is absent from PATH and not directly
  accessible at known absolute paths.

---

## Alternatives Considered

- **No `src/` layout:** rejected - direct imports from the project root during
  `pytest` would shadow the installed package and mask packaging bugs.
- **`models/` layer:** deferred - would be the correct move if publisher or
  generator ever needs to serialize sessions to a database or API format.
- **Third-party MHTML library (e.g. `mailparser`):** rejected - `email` stdlib
  handles PSR output correctly and keeps the mandatory dependency list minimal.
