---
title: Output format
description: What sa stop writes, field by field - report.md, data.json, the screenshots and the replay GIF.
---

`sa stop` writes one folder next to the ZIP, named `<zip name>_output`:

```text
psr_20240115_143000_output/
  report.md            readable report with an AI context block at the top
  data.json            every step as structured data
  action_replay.gif    animated replay, one frame per step (needs the gif extra)
  screenshots/
    step_001.png
    step_002.png
```

Screenshot paths inside both files are relative to this folder, so you can move or zip it as a whole.

## report.md

The report is plain Markdown. It has four parts, in this order.

**Header**

```markdown
# Checkout bug

> Generated by PSR.ai on 2024-01-15 14:31
> Source: `psr_20240115_143000.zip` | Steps: 14
```

**AI Context Block.** A fenced `text` block with one line per step, written to be pasted into an LLM prompt. An HTML comment above it states the line format:

```text
Session: Checkout bug | Source: psr_20240115_143000.zip | Steps: 14 (merged to 9 entries)
[001] 1/15/2024 2:30:04 PM | chrome.exe | User left click on "Add to cart" (button) -> screenshots/step_001.png
[002-006] 1/15/2024 2:30:09 PM | chrome.exe | Continuous text input (5 steps) -> screenshots/step_006.png
[007] 1/15/2024 2:30:21 PM | chrome.exe | User left click on "Pay now" (button) -> screenshots/step_007.png
```

Each line is `[STEP_ID] TIMESTAMP | PROGRAM | ACTION -> SCREENSHOT_PATH`. The screenshot path is `-` when a step has none.

To keep the block short, consecutive steps are merged into one line when all of these hold:

- they happened in the same program;
- their actions start with the same repetitive verb: scroll, type, key, press, input, mouse move or move mouse;
- each is within 5 seconds of the one before.

A merged line has a range ID such as `[2-6]` and one of these summaries: `Continuous scrolling (N steps)`, `Continuous text input (N steps)` or `Repeated action: <action> (N steps)`. It points to the last screenshot in the run. The header line says how many entries remain after merging. Only the context block is merged; the timeline below keeps every step.

**Table of contents.** One link per step.

**Step-by-step timeline.** One section per step, with a table (timestamp, program, action, and the AI description when [`sa analyze`](/psr-ai/ai-analysis/) has run) followed by the screenshot.

## data.json

`data.json` holds the same steps as structured data. The base shape is always present:

```json
{
  "title": "Checkout bug",
  "source": "psr_20240115_143000.zip",
  "generated_at": "2024-01-15T14:31:02.418734+00:00",
  "step_count": 14,
  "steps": [
    {
      "index": 1,
      "label": "User left click on \"Add to cart\" (button)",
      "timestamp": "1/15/2024 2:30:04 PM",
      "ui_element": "Add to cart (button)",
      "program": "chrome.exe",
      "action_text": "User left click on \"Add to cart\" (button)",
      "screenshot": "screenshots/step_001.png"
    }
  ]
}
```

| Step field | Meaning |
|---|---|
| `index` | Step number, starting at 1. |
| `label` | Short description of the step. |
| `timestamp` | When the step happened, as the recording engine reported it. |
| `ui_element` | The element that was acted on, when the engine knows it. |
| `program` | The program or window that had focus. |
| `action_text` | What the user did. |
| `screenshot` | Relative path to the PNG, or empty when there is none. |

### Optional fields

These appear only when the feature that produces them ran.

| Field | Added by | Contents |
|---|---|---|
| `steps[].ai_description` | [`sa analyze`](/psr-ai/ai-analysis/) | A vision model's description of the step. |
| `steps[].browser_context` | [Hidden Context Layer](/psr-ai/hidden-context-layer/) | `network_failures` (method, url, status, error, response_body), `console_errors` (subtype, message, source, stack), `resource_errors` (url, tag), and for the last click in the step: `element`, `page_url`, `page_title`. Empty fields are left out. |
| `steps[].element_html` | `sa stop`, when Playwright is installed | The HTML of the clicked element, fetched again from the page URL in a headless browser. See [Recording](/psr-ai/recording/#sa-stop). |
| `browser_context` (top level) | Hidden Context Layer | `events_total`, `events_merged`, `by_kind` (a count per event kind) and `source`. |
| `os_context` (top level) | `sa stop` | `captured_at`, `active_window`, `platform`, `clipboard_captured`, `clipboard_redacted`, and `clipboard` when you passed `--clipboard`. |

Browser events are matched to steps by time: an event belongs to the last step that started at or before it. Events from before the first step are attached to the first step, so none are dropped.

## Screenshots

`screenshots/step_NNN.png`, numbered to match the step index. With `sa start --low-token` they are at most 512px on the longest side.

## action_replay.gif

One frame per step, 1.5 seconds each. It needs Pillow (`pip install -e ".[gif]"`). `sa stop --no-gif` skips it.
